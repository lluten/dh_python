Start an exercise

Write a little code, run it, and check the result. These steps work for your first exercise and every one after it.

On your computer

1. Open your exercise folder

Create a folder such as exercise-01 inside your python-exercises folder. In VSCodium or VS Code, choose File → Open Folder and select it.

2. Create and activate your environment

A virtual environment keeps the Python packages for your project separate. Create .venv once per exercise folder, then activate it whenever you open a new terminal for that folder.

Choose Terminal → New Terminal in your editor. Run the two lines for your system, one at a time:

WINDOWS · POWERSHELL
python -m venv .venv
.\.venv\Scripts\Activate.ps1
macOS / LINUX · BASH OR ZSH
python3 -m venv .venv
source .venv/bin/activate

After activation, the prompt usually starts with (.venv). Use python on all systems from this point on. Keep using this terminal to install packages and run scripts.

PowerShell blocks activation

In the editor’s terminal menu, open a Command Prompt terminal in the same folder and run .venv\Scripts\activate.bat. You can also stay in PowerShell and use .\.venv\Scripts\python.exe instead of python for installation and running scripts; activation is then unnecessary.

3. Create and save a Python file

Create exercise.py in the exercise folder, alongside .venv (not inside it). Write this small example and save the file with Ctrl+S (Windows/Linux) or Cmd+S (macOS).

PYTHON 
name = "Ada"
print("Hello,", name)

4. Run the file

Save the file, then run this command in your activated terminal:

TERMINAL · ACTIVATED ENVIRONMENT
python exercise.py

The output appears in the terminal:

EXPECTED OUTPUT 
Hello, Ada

5. Edit, save, and run again

Change Ada to your name. Save the file and repeat the command. Now replace the example with the first small step of your exercise. Use print(...) to inspect values as you work.

Keep Python code in the .py file. Commands such as python exercise.py belong in the terminal.

6. Try a small library

humanize makes numbers easier to read. Install it once in this environment:

TERMINAL · ACTIVATED ENVIRONMENT
python -m pip install humanize

Replace the contents of exercise.py with this example, then save it:

PYTHON · exercise.py
import humanize

word_count = 1000000
print(humanize.intcomma(word_count))

Run python exercise.py again. The result is:

EXPECTED OUTPUT
1,000,000

pip install adds a package to your environment. import humanize makes it available in your script. intcomma formats the number with separators. Built-in modules such as math and random need only an import.

When you return to the exercise

Open the same folder and a terminal. Activate the existing environment using only the activation line for your system above, then run python exercise.py. You do not need to create the environment or install its packages again. Use deactivate when you want to leave the environment, or close the terminal.

In your browser

  1. Open Jupyter Cloud or Colab from Setup and create a Python notebook.
  2. Name it exercise-01.ipynb. Enter name = "Ada" and print("Hello,", name) on separate lines in a code cell.
  3. Press Shift + Enter. The output appears below the cell.
  4. Change the name and run the cell again. Add cells for the next steps of the exercise and run them from top to bottom.
  5. Save the notebook and download a copy before you finish.

Jupyter Cloud and Colab manage the running environment, so you do not create or activate a .venv here. To try the same library example, run %pip install humanize in a code cell, then run the import humanize example in the next cell.

A notebook remembers variables from cells you have run. After restarting its kernel or runtime, run the cells again from the top. If your assignment requires a .py file, follow its submission instructions or use the local workflow above.

If it does not run

Python is not found

Check python --version on Windows or python3 --version on macOS/Linux. On Windows, try py --version; if that works, create the environment with py -m venv .venv, then activate it and use python exercise.py. Close and reopen the terminal after installation. Revisit Setup if none works.

“Can’t open file” or the wrong result appears

Save your file. Check that it is named exercise.py, not exercise.py.txt. Open its folder in the editor and create a new terminal there. Use dir on Windows or ls on macOS/Linux to check that the file is listed.

I see >>>, or a terminal command gives a SyntaxError

You are in Python’s interactive prompt. Enter exit(), then run python exercise.py after activating your environment in the terminal. Do not paste terminal commands into your Python file.

Nothing appears, or the program keeps running

Saving a value does not display it: use print(value). Check whether your code is waiting at input(). To stop a running script, press Ctrl+C in the terminal; in a notebook use the stop/interrupt button.

A red error message appears

Read the last line for the error type, then find the line number in your file. Check spelling, quotes, and indentation. Change one thing and run again. If you ask for help, include the code and the full error message.

ModuleNotFoundError, missing model, or missing NLTK data

Activate your exercise’s environment before installing or running code. For the introductory example, run python -m pip install humanize there. For lecture 10b, follow the spaCy and NLTK instructions below. spaCy models and NLTK data need separate downloads.

When your exercise uses data files

Lectures 06a–b · Files, paths, and input/output

Download the exercise data and place it beside exercise.py. For this example, create a UTF-8 text file called text.txt with one sentence in it.

PYTHON 
with open("text.txt", encoding="utf-8") as source:
    text = source.read()
print(text)

Run your script from that folder. A relative path such as text.txt is resolved from the current working folder. In a notebook, upload the file to the running session first. Colab’s Files panel has an upload button; in Jupyter, upload it beside your notebook.

If Python cannot find the file, run this to see which folder it is using:

PYTHON 
import os
print(os.getcwd())

Uploaded session files may disappear when a cloud session ends. Keep your original data and download your results. See lecture 06b resources for references.

When your exercise needs additional packages

Lecture 10b · spaCy and NLTK

Use this section when the exercise asks for a library such as spaCy or NLTK. Built-in modules such as re, os, and random come with Python.

Install packages locally

Activate the environment you already created for this exercise. Install the packages needed for lecture 10b:

TERMINAL · ACTIVATED ENVIRONMENT 
python -m pip install spacy nltk
python -m spacy download en_core_web_sm

Run your exercise with python exercise.py in that same terminal.

Install packages in a notebook

Install into the current notebook kernel by running these in separate code cells:

NOTEBOOK CELL 
%pip install spacy nltk
NOTEBOOK CELL 
import spacy.cli
spacy.cli.download("en_core_web_sm")

Restart the kernel/runtime after installation, then run your code from the top. Repeat installation if a new cloud session no longer has the packages.

Check spaCy and get NLTK data

PYTHON 
import spacy
nlp = spacy.load("en_core_web_sm")
print([token.text for token in nlp("Hello Ada!")])
EXPECTED OUTPUT 
['Hello', 'Ada', '!']

NLTK downloads data separately. Run the following Python code for the tokenisation data introduced in 10b:

PYTHON 
import nltk
nltk.download("punkt_tab")

For later exercises, download the dataset requested by the exercise or NLTK’s error message, such as gutenberg, treebank, stopwords, or wordnet. See 10b resources and 10c resources.
